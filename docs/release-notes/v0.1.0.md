# v0.1.0 Release Notes

## Status

`v0.1.0` is the first CogniSecrets non-alpha release.

## API

The served API version is:

```text
cognilabz.com/v1
```

The release CRD serves and stores `v1`.

The previous `v1alpha1` API has been removed. Alpha compatibility is intentionally not provided for this release.

`SecretReference` source entries require `name`. The `namespace` field is optional; when omitted, the controller resolves the source Secret namespace to the `SecretReference` namespace. Cross-namespace source references must set `namespace` explicitly.

Even for same-namespace source references, the source Secret must explicitly authorize the target namespace through `cognisecrets.cognilabz.com/allowed-namespaces`.

## Compatibility

Releases MUST preserve compatible `v1` behavior unless release notes explicitly document an incompatible change and migration path.

Stable compatibility is not promised until a future `v1` release.

## Migration

Users with old local manifests using `apiVersion: cognilabz.com/v1alpha1` MUST update them to:

```yaml
apiVersion: cognilabz.com/v1
```

No spec field rename is required for the current `SecretReference` schema.

Existing clusters that installed an alpha CRD SHOULD remove or replace that CRD before installing the release manifest, because this release does not serve `v1alpha1`.

## Known Limitations

- `WriteFailed` conformance is covered by reference-implementation unit tests only because operational Kubernetes write and delete failures are not portable to force in a black-box E2E suite.
- `v0.1.0` is the first non-alpha release and should still be evaluated carefully before broad production rollout.
- CogniSecrets does not provide encryption, rotation, generation, external provider access, or key-level authorization.

## Conformance

The local release gate is:

```sh
make release-gate
```

The E2E conformance smoke suite MUST pass against a fresh local `kind` cluster before publication.
