## Changes Since v0.2.2

- Made `spec.sources[].namespace` optional.
- When source `namespace` is omitted, the controller resolves it to the `SecretReference` namespace.
- Added a same-namespace sample manifest.
- Updated the API specification and generated CRD descriptions for optional source namespaces.
- Updated controller tests for omitted source namespace behavior.
- Added Kustomize file headers and README cleanup.

## API And Compatibility

The served API remains:

```text
cognilabz.com/v1
```

`spec.sources[].name` remains required. Cross-namespace references continue to set `spec.sources[].namespace` explicitly.

Same-namespace source references still require explicit source authorization through:

```text
cognisecrets.cognilabz.com/allowed-namespaces
```

## Migration

Existing manifests that already set `spec.sources[].namespace` continue to work.

Users may optionally remove `namespace` from source entries that refer to Secrets in the same namespace as the `SecretReference`, provided the source Secret still authorizes that namespace.

## Known Limitations

- CogniSecrets still does not provide encryption, rotation, generation, external provider access, or key-level authorization.
- Published-image smoke testing should be performed after tag publication.
