# v0.2.0-beta.1 Release Notes

## Status

`v0.2.0-beta.1` is the first CogniSecrets beta release.

## API

The served API version is:

```text
cognilabz.com/v1beta1
```

The beta CRD serves and stores `v1beta1`.

The previous `v1alpha1` API has been removed. Alpha compatibility is intentionally not provided for this release.

## Compatibility

Beta releases SHOULD preserve compatible `v1beta1` behavior unless release notes explicitly document an incompatible change and migration path.

Stable compatibility is not promised until a future `v1` release.

## Migration

Users with old local manifests using `apiVersion: cognilabz.com/v1alpha1` MUST update them to:

```yaml
apiVersion: cognilabz.com/v1beta1
```

No spec field rename is required for the current `SecretReference` schema.

Existing clusters that installed an alpha CRD SHOULD remove or replace that CRD before installing the beta manifest, because this release does not serve `v1alpha1`.

## Known Limitations

- `WriteFailed` conformance is covered by reference-implementation unit tests only because operational Kubernetes write and delete failures are not portable to force in a black-box E2E suite.
- Beta releases are intended for test and early production evaluation clusters.
- CogniSecrets does not provide encryption, rotation, generation, external provider access, or key-level authorization.

## Conformance

The local beta release gate is:

```sh
make beta-gate
```

The E2E conformance smoke suite MUST pass against a fresh local `kind` cluster before publication.

Known uncovered normative MUST statements:

```text
None known, except WriteFailed portability as described above.
```
